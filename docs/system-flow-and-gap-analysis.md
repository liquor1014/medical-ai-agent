# 医疗 AI Agent 系统业务流程与功能完善点梳理

> 分析日期：2026-11-17
> 分析范围：`web`（Vue3）、`backend`（Spring Boot）、`ai-service`（FastAPI + LangGraph）、`infra`（PostgreSQL / Redis / Qdrant / MinIO）
> 方法：按「入口 → 交互步骤 → 服务端处理 → 数据落库 → 异常分支」逐模块走查代码，结论均附代码位置，未验证的推测不作结论。

## 1. 系统总览

### 1.1 分层架构

| 层 | 技术栈 | 核心职责 |
| --- | --- | --- |
| 前端 | Vue3 + TypeScript + Element Plus + Vite | 登录/租户选择、文件库、问答（SSE）、报表、审计、评测、模型健康 |
| 后端 | Spring Boot 3.4 + JWT + Redis Session | 认证鉴权、租户隔离、文件/报表/评测/审计业务、AI 服务代理 |
| AI 服务 | FastAPI + LangGraph + Qdrant | 意图路由、RAG 检索、NL2SQL、报表生成、复核、模型路由与降级 |
| 存储 | PostgreSQL / Redis / Qdrant / MinIO | 业务数据、登录会话、向量索引、原始文档 |

### 1.2 身份与租户模型

1. 登录签发 JWT（含 `username / tenantId / role / jti`），并在 Redis 建立会话；登出吊销 `jti`。
2. `TenantInterceptor` 先读取 `X-Tenant-Id`（缺省 `hospital-demo`）；`AuthInterceptor` 校验 Token 后**以 Token 内租户覆盖**请求头租户，避免改头越权。
3. 所有业务查询以 `TenantContext` 中的 `tenant_id` 过滤（文件、会话、报表、审计、向量检索过滤条件一致）。
4. `role` 已写入数据库和 JWT，但**未参与任何接口鉴权或菜单控制**（见 3.7-01）。

### 1.3 端到端主链路

```
登录/选租户
  → 文件库上传文档（MinIO + 元数据入库）
  → 异步解析（AI /api/parse：下载 → 多模态解析 → 分块 → 入库 + 向量化）
  → 智能问答（意图路由 → 检索 / NL2SQL / 报表 / 闲聊 / 澄清 → 回答 → 复核）
  → 会话与事件落库（chat_session / message / chat_event）
  → 报表中心查看与 CSV 导出
  → 审计日志 / 评测看板 / 模型健康观测
```

## 2. 业务流程逐模块拆解

### 2.1 登录 / 注册 / 租户

**操作链路**

1. 打开登录页 → 拉取租户列表（`/api/tenants/list`，当前为固定三条）→ 必选所属租户。
2. 输入用户名/密码 → 登录 → 成功跳转 `/files`；失败展示 401/403 文案。
3. 切换到注册：增加昵称、确认密码 → 注册成功后自动登录，角色固定 `doctor`。
4. 退出登录 → 吊销当前 Token 的 Redis 会话 → 清理本地登录态。

**流转规则**

| 环节 | 规则 | 证据 |
| --- | --- | --- |
| 登录 | 按 `tenant_id + username` 查用户，BCrypt 校验；禁用账号 403 | `AuthService.java:L33-L44` |
| 注册 | 用户名 3-32 位字母/数字/下划线；密码 6-64 位；同租户重名 409 | `AuthService.java:L49-L70`、`RegisterRequest.java:L14-L23` |
| 租户 | 注册直接绑定当前租户，无需二次选择 | `AuthService.java:L49-L61` |
| 登出 | 仅吊销当前 jti，其他端会话不受影响 | `AuthService.java:L98-L104` |
| Token 校验 | 签名/有效期 + Redis 会话存在性双重校验 | `AuthService.java:L87-L93` |

**异常与断点**：租户列表硬编码、无找回密码、无密码复杂度要求、无登录失败次数限制。

### 2.2 文件库与文档解析

**操作链路**

1. 进入文件库 → 列表按租户返回全部文档（状态：`pending / parsing / completed / failed`）。
2. 上传文件 → 后端写入 MinIO（`{tenantId}/{uuid}_{filename}`）→ 元数据入库 → 立即返回 `pending`。
3. 异步解析：状态置 `parsing` → 调 AI `/api/parse` → 成功写 `completed` + 页数/分块数，异常写 `failed`。
4. 前端定时刷新列表观察状态；支持关键词、状态、类型筛选。
5. 文档详情 → 「就这份文档提问」跳转问答页（携带文档上下文参数）；删除需二次确认。
6. 删除：先删 MinIO 对象（失败仅告警）→ 再删数据库记录。

**流转规则与证据**

| 环节 | 规则 | 证据 |
| --- | --- | --- |
| 上传 | 服务端限制 50MB/请求 100MB；按扩展名推断 docType | `application.yml:L23-L24`、`FileService.java:L121-L133` |
| 解析 | `@Async` 手动传递 TenantContext；失败统一置 failed | `AsyncParseService.java:L34-L77` |
| 解析产物 | 文本/表格/图片分块后同时入库 PostgreSQL 与 Qdrant | `parse.py:L58-L78` |
| 删除 | MinIO 删除失败被忽略，DB 仍删除 | `FileService.java:L103-L119` |
| 租户隔离 | 列表/详情/删除均按 `TenantContext` 查询 | `FileService.java:L83-L98` |

**异常与断点**：解析失败无重试入口；无解析进度百分比；无完成通知；列表一次性全量返回无分页；无下载/预览接口；无批量操作。

### 2.3 智能问答（核心链路）

#### 2.3.1 入口与历史会话

1. 进入问答页 → 默认加载历史会话列表（租户内，支持关键词、时间范围、条数）。
2. 点击历史会话 → 拉取完整消息流恢复上下文（用户/助手消息、引用、SQL、报表、review、错误）。
3. 点击「新会话」→ 清空当前上下文，生成新的 `session_id`。
4. 活跃会话高亮，切换时平滑过渡。

证据：`ChatView.vue:L2-L55`、`ChatView.vue:L57-L74`、`chat.ts:L52-L69`。

#### 2.3.2 一次提问的完整执行链路

```
发送问题
 → POST /api/chat/stream（后端注入 tenant_id/session_id，SSE 代理）
 → AI：upsert 会话 → 加载最近 10 轮历史 → LangGraph 执行
 → router 意图分类
     ├─ CLARIFY   → 反问提示
     ├─ RETRIEVAL → 检索节点 → answer 节点
     ├─ NL2SQL    → SQL 生成/校验/执行
     ├─ REPORT    → NL2SQL 结果 → 报表节点
     └─ CHAT      → 直接 LLM 闲聊
 → review 质量复核
 → 流式返回 token / citations / sql / result / report / review / done
 → 保存 user/assistant 消息 + SSE 事件
```

| 节点 | 职责 | 分支条件 | 失败降级 |
| --- | --- | --- | --- |
| router | 规则意图分类 | 关键词优先级匹配，未知走 `chat` | 异常默认 `retrieval`，错误码 `ROUTER_FAIL` |
| clarify | 歧义反问 | 空输入/纯符号/文档与数据意图同时命中 | 固定兜底文案，`CLARIFY_FAIL` |
| retrieval | Qdrant 检索 + 上下文拼装 | 检索类问题 | 空上下文继续回答，`RETRIEVAL_FAIL` |
| answer | 基于上下文生成回答 | retrieval 之后 | mock 兜底，`ANSWER_FAIL` |
| chat | 自由对话 | 问候/闲聊/通用问题 | 确定性兜底文案，`CHAT_FAIL` |
| nl2sql | 生成、校验、执行 SQL | 数据统计类问题 | 失败状态 + 空结果，`NL2SQL_FAIL` |
| report | 生成标题/图表/摘要 | 报表类问题 | 失败状态，`REPORT_FAIL` |
| review | 规则质量检查与免责声明 | 各回答节点之后 | 跳过复核保留原回答，`REVIEW_FAIL` |

证据：`graph.py:L58-L89`、`graph.py:L122-L143`、`graph.py:L146-L198`、`graph.py:L251-L334`、`graph.py:L356-L385`、`chat.py:L87-L158`。

#### 2.3.3 流式事件与持久化

1. `session_id` 由前端生成或后端补齐；会话唯一键为 `tenant_id + external_id`。
2. 历史上下文取最近 10 轮消息注入 `GraphState.history_messages`。
3. 每轮分别写入 user / assistant 消息（含 citations），并写 `chat_event` 事件时间线（token 事件存累计文本）。
4. 结束事件返回 `completed_with_degradation`、失败记录与 review 结果。
5. 所有数据库写入均为 **best-effort**，失败仅记录日志，不阻断对话。

证据：`chat.py:L365-L395`、`chat_store.py:L37-L71`、`chat_store.py:L107-L137`、`chat_store.py:L256-L335`。

#### 2.3.4 前端交互能力（已具备）

- Enter 发送 / Shift+Enter 换行，流式期间禁用输入。
- 「停止」中断生成，状态显示“已停止生成”。
- 单轮「重新生成」。
- 引用文档/报表可点击打开详情。
- 错误行内展示 + SQL 预览 + 图表/表格 + review 标签。

证据：`ChatView.vue:L188-L228`、`ChatView.vue:L234-L260`。

### 2.4 报表中心

1. 进入报表中心 → 按租户加载最近 50 条报表。
2. 点击报表 → 详情展示图表 / 数据表 / SQL 三个标签页。
3. 导出 CSV（UTF-8 BOM，Excel 可直接打开）；支持复制 SQL。
4. 详情加载失败会清空当前选中项并提示。

证据：`ReportsView.vue:L135-L207`、`ReportService.java:L35-L66`、`ReportController.java:L24-L42`。

**断点**：无分页/搜索/状态筛选；无删除/重命名/分享；仅 CSV，无 Excel/PDF；列表固定 50 条上限且无“加载更多”。

### 2.5 评测看板

1. 进入评测看板 → 读取 AI 评测脚本产出的静态 JSON。
2. 展示总体指标、路由信息、延迟；支持类型/结果/关键词筛选与服务端分页（上限 100）。
3. 点击评测项 → 抽屉查看检索命中、SQL、答案明细。
4. 结果文件不存在时提示“请先运行评测脚本”。

证据：`EvalService.java:L31-L42`、`EvalService.java:L47-L91`、`EvalService.java:L96-L109`、`EvalView.vue:L67-L146`。

**断点**：页面无法发起评测；无历史版本对比/趋势；结果全租户共享，未按租户隔离。

### 2.6 审计日志

1. 进入审计页 → 加载统计卡片（总数、成功/失败、24h、动作分布）。
2. 按动作/结果筛选 + 分页浏览（页大小上限 50）。
3. 单行复制 SQL Hash。

证据：`AuditService.java:L20-L35`、`AuditView.vue:L13-L120`。

**断点**：无导出；无日志详情；当前以 SQL 审计为主，登录、文件、模型配置等管理操作未纳入统一审计。

### 2.7 模型健康与提供者管理

1. 进入模型健康页 → 展示 4 张统计卡、模型提供者列表、任务路由链、24h 明细、最近调用日志（30s 轮询）。
2. 新增模型：名称/模型/Base URL/API Key/启用状态 → 二次确认 → 保存后即时替换列表并静默刷新。
3. 编辑模型：回填全部参数，名称锁定，Key 留空则沿用原值。
4. 启停：操作栏切换 → 二次确认 → 即时更新标签与卡片样式；停用后从路由可用集合剔除。
5. 恢复默认路由（内存级）；试调用按任务执行并展示降级链路。

证据：`ModelView.vue:L66-L127`、`ModelView.vue:L256-L347`、`ModelView.vue:L406-L450`、`ModelView.vue:L586-L725`、`models.py:L219-L264`、`providers.py:L251-L265`、`providers.py:L374-L437`。

**断点**：无删除提供者；路由切换无页面编辑入口且不持久化；API Key 明文入库；无配置变更历史与操作人。

### 2.8 横向能力：异常、降级与反馈

| 能力 | 现状 |
| --- | --- |
| 节点级降级 | 非核心节点失败继续主流程，核心节点返回结构化错误码 |
| 模型降级 | 按路由依次尝试，全部失败进入 mock，并记录调用日志 |
| 前端反馈 | 新增/编辑/启停/删除/重置均有确认与消息提示 |
| 持久化 | 会话/事件/模型配置落库；会话类写入失败静默 |
| 可观测 | 模型调用日志、24h 统计、SSE 事件时间线、审计日志 |

## 4. 优先级建议

### P0（安全与主链路可信度）

1. RBAC：模型配置、审计、评测仅管理员可见/可操作；后端按 role 校验，前端按角色隐藏菜单。
2. API Key 加密存储（KMS/环境密钥）与日志脱敏。
3. 会话持久化失败可观测：失败计数/告警，前端在 `done` 事件提示“历史可能未保存”。
4. 检索阈值 + 去重 + 引用页码定位，提升医疗问答可核查性。
5. 会话重命名/删除与列表治理能力。

### P1（效率与闭环）

1. 文件解析重试、进度、完成通知；批量删除/下载。
2. 模型提供者删除；路由编辑可视化并持久化；配置变更记录。
3. 报表/审计导出与分页；报表溯源到对话。
4. 评测任务化：页面发起、版本对比、按租户隔离。
5. 意图置信度展示与“答案不对/意图错了”纠正反馈。

### P2（体验优化）

1. 统一错误组件与恢复动作；上传取消与前端预校验。
2. 对话复制/导出、点赞点踩。
3. 响应式导航与表格适配、骨架屏。
4. 限流与并发隔离（问答/解析分池）。

## 5. 回归验证建议

| 改进项 | 验证要点 |
| --- | --- |
| RBAC | 医生账号访问 `/models`、`/audit`、`/eval` 应 403 或菜单不可见；管理员正常 |
| Key 加密 | 数据库中不可见明文；页面仍显示掩码；重启后调用正常 |
| 检索阈值/引用定位 | 低相关文档不进入引用；点击引用可定位页码并高亮 |
| 会话治理 | 重命名/删除后刷新仍生效；删除会话不影响其他租户 |
| 解析重试 | 人为制造失败后重试成功，状态从 failed→parsing→completed |
| 路由持久化 | 修改路由后重启 AI 服务仍保持；停用提供者不参与调用 |
| 导出/分页 | 大数据量下首屏时间可控，导出内容与筛选条件一致 |
